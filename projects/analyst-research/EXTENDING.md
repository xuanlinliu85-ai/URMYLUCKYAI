# 后续添加新分析师：Codex 执行规范

这个包不是一次性项目，而是一个可以持续扩展的“分析师天团”框架。

以后当用户说：

- “再加一个 XXX 研究员”
- “把 XXX 公众号炼化进去”
- “新增一个策略框架”
- “加入某个研究团队/博主”
- “把这位分析师并入天团”

Codex 必须按照下面流程执行，而不是随意新增 Prompt。

---

# 一、标准扩展流程

## Step 1：确认对象

确认：
- 名称
- 来源类型：公众号 / 研究机构 / 博客 / 研报作者 / 播客 / GitHub / 其他
- 是否有明确代表文章
- 是否有公开可访问历史内容

如果只有名称：
- 先查公开资料
- 确认不要认错同名账号

## Step 2：采集“足够但不过度”的样本

目标不是下载全部文章，而是找到：
- 早期方法论文章
- 中期框架演化文章
- 最近 6-12 个月代表文章
- 至少 2-3 个不同主题
- 如果有明显观点转向，必须覆盖转折点

优先级：
1. 原始作者/机构页面
2. 官方公众号原文
3. 授权转载
4. 高质量转载
5. 标题索引/摘要

版权规则：
- 不镜像完整付费文章
- 不把全部原文塞进 Skill
- 只保存：标题、日期、来源、核心论点、因果链、指标、反证、框架演化
- 引文只保留必要的极短片段

## Step 3：识别“真正独特能力”

不要因为有新作者就强行新增角色。

必须回答：

1. 这个分析师最强的 3-5 个问题是什么？
2. 和已有分析师重复多少？
3. 它补的是：
   - 制度
   - 宏观
   - 流动性
   - 定价
   - 资金
   - 交易
   - 行业
   - 量化
   - 组合
   - 风险管理
   哪一层？
4. 若重复度高，是否更应该把其框架合并到现有 Skill，而不是新建 Skill？

只有存在稳定、独特、可复用方法时，才创建新 Skill。

## Step 4：炼化，不模仿

必须提炼：

- 核心总模型
- 固定分析顺序
- 常用变量
- 常见因果链
- 历史类比方法
- 资产映射
- 反证机制
- 数据纪律
- 来源纪律
- 禁令

严禁：
- 模仿作者口癖
- 模仿标志性文风
- 把旧观点当当前观点
- 把第三方转载自动算成作者观点
- 把历史相关性当因果

## Step 5：生成标准 Skill

新 Skill 目录：

```text
.agents/skills/<skill-name>/
├── SKILL.md
├── agents/
│   └── openai.yaml
├── references/
│   ├── framework.md
│   ├── source-map.md
│   └── article-schema.json
└── scripts/
    └── normalize_article.py
```

必须使用 `EXTENSION_KIT/skill-template/` 作为骨架。

## Step 6：加入 Router

修改：

```text
.agents/skills/analyst-dream-team-router/
```

至少更新：

- `SKILL.md`
- `references/routing-matrix.md`

需要写清：

1. 新分析师最适合哪些问题
2. 哪些问题它是主分析师
3. 哪些问题它只做辅助
4. 和谁搭配最互补
5. 和谁最容易重复
6. 如何避免重复分工

## Step 7：更新 Registry

修改根目录：

```text
ANALYST_REGISTRY.json
```

字段至少包括：

- name
- skill_name
- status
- role
- strengths
- avoid_overlap_with
- preferred_partners
- source_note

## Step 8：更新版本

更新：
- `manifest.json`
- `CHANGELOG.md`
- 版本号

版本建议：
- 新增分析师：minor version，例如 2.0 → 2.1
- Router重大改造：major version，例如 2.x → 3.0
- 小修：patch version，例如 2.1.0 → 2.1.1

## Step 9：自检

至少做以下测试：

### 单人调用
确认新 Skill 能独立工作。

### Router 调用
确认总控能在合适问题下选中它。

### 避免误调用
确认不相关的问题不会被选中。

### 去重
确认新旧分析师不会输出完全相同内容。

### 冲突处理
若新分析师与旧框架结论相反，Router 必须能解释：
- 数据口径
- 时间周期
- 因果权重
- 真正方向分歧

---

# 二、总控原则

以后分析师越来越多后，不允许“每次全部调用”。

默认：

- 单一问题：1-2 位
- 跨层问题：2-3 位
- 系统性重大问题：3-4 位
- 全员会诊：仅用户明确要求时

Router 应优先选择“互补”，而不是“相似”。

---

# 三、未来可新增的角色类型

当前天团已经覆盖：

- 中国制度/PPI/产业
- Fed/财政/美债
- 定价/资金/拥挤
- Money View/美元 plumbing
- Global Macro Trading/Relative Value

未来更值得补的是：

- A股产业/科技研究
- 商品/周期
- 国内政策/财政
- 量化市场状态
- 基金配置/组合
- 信用债
- 地产
- AI产业链
- 地缘政治
- 风险管理/尾部对冲

不要为了数量而加人。

---

# 四、Codex 接到“新增分析师”任务时的默认输出

完成后必须向用户交付：

1. 新分析师 Skill
2. 更新后的 Router
3. 更新后的完整天团包
4. 简要说明：
   - 新角色定位
   - 与现有角色差异
   - 哪些问题会自动调用它

如果用户最终目标是 Codex 项目，优先更新完整项目包，而不是只给孤立 Skill。

新增或重炼任何分析师前，必须先读取根目录 `CORPUS_POLICY.md` 并通过 `Corpus Audit`。不得用少量近期文章直接生成稳定 DNA；短文、标题页、翻译、嘉宾内容必须降权。
